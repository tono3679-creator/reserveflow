## 共通レイアウト

- 左に固定サイドバー（ダークネイビー）。幅 1024px 未満はヘッダーのボタンで開くドロワー。
- ヘッダー：店舗の切り替え（所属する企業の店舗だけ）、今日の日付、ユーザーメニュー（デモでは立場の切り替え・初期化・終了）。
- 各画面：パンくずリスト・ページタイトル・主要操作ボタン（`PageHeader`）。
- 読み込み中はスケルトン、失敗時は再読み込みボタンつきのエラー表示、空のときは空状態の表示。
- 保存結果はトースト、入力の誤りは項目の下に表示。破壊的な操作は確認ダイアログを挟む。

## Phase 1 で実装したもの

- デモ：トップページから業種を選ぶと、訪問者専用の4店舗（各 430〜560 件の予約・90〜140 名の顧客、約6か月分）を生成。オーナー・マネージャー・スタッフの立場の切り替え、初期化、終了（データ削除）。
- ログイン：メール＋パスワード（Supabase Auth／ローカル）。失敗が続くと一時的に受け付けない。
- 店舗の切り替え（複数企業・複数店舗）。
- ダッシュボード：本日の予約（時刻・顧客・サービス・担当・ステータス）と件数。売上見込みはオーナーだけ。
- 店舗設定：店舗情報、曜日ごとの営業時間・定休日、予約受付・キャンセルのルール、リマインドの有無。

## Phase 2 で実装したもの

- **予約の登録・変更（DB 関数）**：`create_booking` / `update_booking` / `set_booking_status`。役割の確認、担当できるサービスか、設備の自動割り当て、楽観ロック（`version`）、ステータスの履歴・通知イベント・操作履歴をまとめて1トランザクションで記録。同じスタッフ・同じ設備の重なりは排他制約が必ず拒否する。
- **空き枠判定エンジン**（`src/lib/scheduling/engine.ts`）：営業時間・定休日・臨時休業、スタッフの勤務・休憩・休暇・勤務変更、担当サービス、既存予約（前後の準備・片付け時間を含む）、設備の空き、受付の締め切り・受付期間。管理画面では「営業時間外」「勤務時間外」などは確認すれば登録でき、重なり・設備不足・担当外は登録できない。
- **予約カレンダー**：月・週・日・スタッフ別。空き時間の選択で新規予約、ドラッグで日時変更、端のドラッグで時間の変更、スタッフ別表示では列をまたいで担当を変更。勤務時間外・休憩は網かけ。キャンセル・無断キャンセルの表示切り替え、スタッフでの絞り込み。スマートフォンでは日表示から始まる。
- **予約一覧・詳細**：キーワード・ステータス・担当・サービス・期間での検索、日時・料金・受付日での並び替え、ページ送り（すべてサーバー側）。詳細ではステータス変更（キャンセル・無断キャンセルは理由つきの確認）、内容の編集、ステータスの履歴。
- **顧客管理**：検索・セグメント（VIP／リピーター／新規／休眠／未来店）での絞り込み・並び替え。詳細では来店回数・累計利用額・平均単価・平均来店間隔・無断キャンセル率・よく利用するサービス、予約の履歴、メモ、編集、削除（予約のない顧客だけ）。セグメントの基準は店舗設定で変更できる。
- **スタッフ管理**：一覧に直近30日の予約件数・稼働率（予約時間 ÷ 休憩を除いた勤務時間）・無断キャンセル率・売上（オーナーのみ）。詳細で週の基本勤務（休憩つき）、休暇・特定日の勤務変更（その日の予約件数を表示）、基本情報・担当サービス（オーナーのみ）。今後の予約があるスタッフは停止できない。
- **メニュー・サービス**：料金・所要時間・準備／片付け時間・説明・色・Web予約への表示・担当スタッフ・使う設備。設備（部屋・席・機材）の追加・編集・停止。予約のあるサービス・設備は削除できず「停止」にする。

## Phase 3 で実装したもの

- **公開予約ページ** `/book/[slug]`（ログイン不要・スマートフォン向け）：サービス → スタッフ（指名なし可。店舗設定で「指名なし」の業種は省略）→ 日付（2週間ずつ、空きの多さを ◎○× で表示）→ 時間 → お客様情報 → 内容の確認（キャンセルポリシーへの同意）→ 確定 → 完了。空き状況は選ぶたびにサーバーで計算し、確定の直前にもう一度判定する。埋まっていたら時間の選択に戻す。
- **公開予約の判定**：管理画面と同じ空き枠エンジンを使い、お客様の予約では営業時間外・勤務時間外・受付の締め切り・受付期間外もすべて不可。「指名なし」はその日の予約が少ない空きスタッフを割り当てる。最後は DB の排他制約が重複を拒否する。
- **顧客の扱い**：メールと電話番号の両方が一致する顧客がいればその顧客の予約にし、いなければ新しく登録する（既存の顧客情報はお客様側からは書き換えない）。
- **予約の確認・変更・キャンセル** `/book/[slug]/manage/[token]`：トークンは予約 ID と秘密の値（`APP_SECRET`）から作る HMAC-SHA256（256 ビット）。DB にはハッシュだけを保存する。日時・スタッフの変更とキャンセルは、店舗設定の締め切り（開始の n 時間前）まで。過ぎたら理由と店舗の電話番号を表示する。
- **公開 API の保護**：接続元ごとの回数制限（空き状況 120 回／10分、予約 10 件／時、変更・キャンセル 20 回／時）、同じサイトからの JSON の送信だけを受け付ける、入力は zod で検証、エラーは内部情報を出さない文にする。
- **通知**：予約確定・変更・キャンセル・前日リマインド・当日リマインドを「通知イベント」として記録（同じ出来事は `dedupe_key` で1件だけ）。送信の記録は1イベント1件（`unique (event_id, channel)`）で、先に記録を作れた処理だけが送るので二重送信しない。失敗は3回まで再試行。
- **送信の差し替え口**（`src/lib/notifications/adapters.ts`）：デモの企業、または `RESEND_API_KEY`・`NOTIFY_FROM_EMAIL` が未設定のときはメールを送らず「デモ表示」として内容を記録する。設定すると Resend で送る。
- **通知管理** `/notifications`：種類・状態・顧客名での絞り込み、状態ごとの件数（直近30日）、件名と本文の表示、送信失敗の再送、リマインドの手動実行。
- **定期処理**（`vercel.json`）：毎朝 8:00（日本時間）にリマインドを作成して未送信の通知を送る、毎日 3:00 に期限切れのデモを削除する。どちらも `CRON_SECRET` がないと動かない。
- 導線：トップページの各業種から見本の店舗の予約ページへ、予約カレンダーの「公開予約ページ」、店舗設定の「予約受付・キャンセル」タブに URL。

## Phase 4 で実装したもの

集計はすべて実際の予約データから SQL で計算します（`src/lib/analytics/metrics.ts`）。架空の数値や、根拠のない分析文は出しません。

### 分析の定義

| 用語 | 定義 |
| --- | --- |
| 対象の予約 | 開始予定時刻が対象期間（店舗のタイムゾーンでの日付）に含まれる予約 |
| 予約件数 | 対象の予約から、顧客キャンセル・店舗キャンセルを除いたもの（無断キャンセル・今後の予定は含む） |
| 来店 | 来店済み・サービス完了（顧客セグメントの「来店」と同じ） |
| 売上 | 来店した予約の料金の合計（予定の料金。入金額ではない） |
| 平均客単価 | 売上 ÷ 来店件数 |
| 無断キャンセル率 | 無断キャンセル件数 ÷ 対象予約件数 × 100。母数は対象の予約のうち、いまより前に始まるもの（将来の予約と店舗キャンセルは除く） |
| 顧客キャンセル率 | 顧客キャンセル件数 ÷ 同じ母数 |
| 推定機会損失額 | 無断キャンセルになった予約の予定料金の合計（実際の逸失利益とは異なると画面に明記） |
| リピート率 | 対象期間に来店した顧客のうち、期間の終わりまでにこの店舗で累計2回以上来店した顧客の割合（顧客は重複して数えない） |
| 新規顧客 | 初めての来店が対象期間にある顧客 |
| 平均来店回数 | 対象期間の来店件数 ÷ 来店顧客数 |
| 平均来店間隔 | 対象期間の来店について、同じ顧客の前回の来店からの日数の平均 |
| 休眠顧客数 | いま時点で、最後の来店から休眠の日数（顧客セグメントの基準）以上たち、今後の予約がない顧客 |
| 30・60・90日再来店率 | 初回来店が対象期間にある顧客のうち、初回から N 日以内に再来店した割合。初回から N 日たっていない顧客は「観測中」として母数から除く |
| 予約枠稼働率 | 予約で埋まった時間（前後の準備時間を含む）÷ 予約を受けられる時間。スタッフがいる店舗はスタッフの勤務時間（休憩・休暇を除く）、いない店舗は設備ごとの営業時間。はみ出した分は数えない。今日より後の日は含めない |
| スタッフ別・サービス別のリピート率 | 期間内にそのスタッフ（サービス）を利用した顧客のうち、期間の終わりまでに同じスタッフ（サービス）を2回以上利用した顧客の割合 |
| 比べる期間 | 1か月の中で月の初日から始まる期間は前の月の同じ範囲（今月 → 先月の同じ日数）、それ以外は直前の同じ日数。件数・金額は増減率、率はポイント差で示す |

### 画面

- **ダッシュボード**（オーナー・マネージャー）：KPI 8種（本日の予約件数・本日の売上・今月の売上・今月の予約件数・リピート率・無断キャンセル率・平均客単価・予約枠稼働率）と前の期間との比較。売上の3種はオーナーのみ。グラフ6種（月別売上推移〔マネージャーは月別予約件数〕・日別予約件数・予約ステータス構成・人気サービス・新規／リピーター・曜日別予約数）。スタッフの立場では本日の担当予約だけ。
- **インサイト**：決めた基準（`src/lib/analytics/insights.ts` の `INSIGHT_RULES`）を満たしたときだけ、根拠の数値つきで出す。曜日ごとの稼働率の偏り（直近8週）、リピート率・無断キャンセル率の変化（直近30日と前の30日。母数が少ないときは比べない）、明日の60分以上の空き、最も予約の多いサービス。
- **売上分析**：期間の選択（今月・先月・直近30/90/180日・1年・任意）、売上・来店件数・平均客単価・予約件数と前の期間比、日別（92日を超えると月別）・月別・曜日別・開始時刻別の売上、サービス別の構成と表、スタッフ別（担当予約・来店・売上・平均客単価・稼働率・リピート率）。
- **顧客分析 › 無断キャンセル**：母数・件数・率・顧客キャンセル率・推定機会損失額（金額はオーナーのみ）、月別の推移、曜日別・時間帯別・サービス別の発生率、顧客別の発生回数、対策の状況（リマインド・キャンセルポリシー・変更の導線・キャンセル履歴）。利用制限は自動では行わない。
- **顧客分析 › リピート率**：来店顧客数・リピーター数・リピート率・平均来店回数・平均来店間隔・休眠顧客数、30/60/90日再来店率（確定した母数と観測中の人数を表示）、月別リピート率、新規／既存の構成、来店回数の分布、再来店までの日数の分布、スタッフ別・サービス別のリピート率。
- **スタッフ管理**：一覧・詳細の実績（直近30日）を分析画面と同じ定義に統一し、平均客単価・リピート率と月別の推移グラフを追加。
- どのグラフも「表で見る」で数値を表として確認できる（色が見分けにくい場合・読み上げのため）。
